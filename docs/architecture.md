# VeilRoom MVP 安全架构

## 目标与安全边界

VeilRoom 是一个无账户、限两人的临时会话服务。后端只处理会话状态、在线状态和端到端加密后的密文信封；它不持有、推导、持久化或记录用于解密的密钥。消息与文件分片均不会写入数据库、磁盘、缓存或日志。会话绝对到期时间为创建后的十分钟；任何参与者明确退出即撤销其参与者能力并开始一分钟销毁倒计时；两人均退出时立即销毁。最先到达的销毁条件具有优先级。

| 资产 | 处理位置 | 持久化策略 | 销毁策略 |
| --- | --- | --- | --- |
| 会话 ID、参与者能力与状态 | Go 服务内存 | 仅内存；进程重启即失效 | 过期、双退出或强制退出时删除 |
| 聊天消息 | WebSocket 中继缓冲区 | 不缓存、不落盘、不写日志 | 转发完成即释放 |
| 加密密钥与私钥 | 浏览器内存 | 不使用 LocalStorage、IndexedDB 或 Cookie | 退出、页面卸载或会话结束时清空引用 |
| 文件密文分片 | WebSocket 转发缓冲与两端浏览器内存 | 不上传对象存储，不写磁盘 | 转发后释放；接收端会话关闭时清空分片引用 |
| 文件名、类型、大小 | AES-GCM 加密的文件要约 | 仅在参与者浏览器内存中解密 | 随会话内存状态释放 |

> **可信边界**：TLS 保护传输层，而 E2EE 保护内容。Go 服务可看到会话 ID、连接时间、密文大小与网络地址等最小运行元数据，但不具备读取消息或文件明文的密钥材料。

## 邀请与密钥协商

发起端使用 `crypto/rand` 生成 32 字节随机会话 ID 和 32 字节配对秘密。分享链接采用 `https://host/s/<session-id>#<pairing-secret>` 形式；片段部分不会随 HTTP 请求发送。会话 ID 用于路由，配对秘密仅保留在两个浏览器内存中。

两端分别生成一次性 ECDH P-256 密钥对。双方通过 WebSocket 交换公钥及基于配对秘密的 HMAC-SHA-256 握手证明。验证完成后，浏览器从 ECDH 共享位、配对秘密和按固定顺序排列的公钥指纹使用 HKDF-SHA-256 导出 AES-GCM-256 会话密钥。每条消息和每个文件分片使用唯一 96 位 nonce；加密附加数据绑定协议版本、会话 ID、发送方角色、对象 ID 和序号，防止跨会话、跨角色或跨分片替换。

该方案使后端只能转发公钥、握手证明和 AES-GCM 密文。配对秘密不经网络发送，服务端无法伪造双方通过的握手证明，也无法推导会话密钥。客户端一旦无法验证握手、检测到重复 nonce、消息序号回退或协议字段异常，必须关闭连接、清空本地密钥并显示安全失败状态。

## 会话状态机

| 状态 | 允许事件 | 拒绝事件 | 结果 |
| --- | --- | --- | --- |
| `WAITING` | 发起者连接；一个受邀加入者连接 | 第二个加入者、未知角色 | 两人就绪后转入 `LOCKED` |
| `LOCKED` | 仅两个既有参与者发送密文、文件协议和心跳 | 任何新连接、重新加入、角色切换 | 任一明确退出转入 `CLOSING` |
| `CLOSING` | 仍在线的参与者接收倒计时与销毁通知 | 退出者重连、第三方加入、内容发送 | 一分钟到期、十分钟到期或双方退出时销毁 |
| `DESTROYED` | 无 | 所有事件 | 连接关闭，服务端状态与浏览器密钥、消息、文件分片引用全部释放 |

会话创建时记录不可变的 `expiresAt = createdAt + 10min`。显式退出会立刻废弃该参与者的随机能力令牌，因而即使其保留邀请链接也不能重新加入。连接关闭一律被安全视为离开，因而不会为网络恢复保留访问能力或内容；明确退出、销毁通知和客户端页内关闭均不允许恢复。两端离开时不等待一分钟，立即进入销毁流程。

## 文件传输

文件内容、原始名称与 MIME 类型均在浏览器中加密。客户端把每个文件切分为最多 24 KiB 的明文块，为每个块生成独立的 AES-GCM nonce，并将会话 ID、发送方角色、文件 ID、块索引和严格递增的消息序号绑定为附加认证数据。服务端仅转发不超过协议大小上限的密文 JSON 信封，既不落盘也不保存分片清单。接收端仅在浏览器内存中保留已成功解密的分片；所有分片抵达后，用户可从本地 Blob 下载原文件。

该设计不依赖 S3、对象存储或任何第三方数据服务。服务端关闭会话、参与者主动离开或协议校验失败时，客户端关闭 WebSocket，清空 AES-GCM 会话密钥、邀请能力、消息状态和全部内存分片引用。单文件上限为 2 MiB，以控制两端内存和 WebSocket 帧负载；不完整、重复、越界、重放或认证失败的分片会使客户端安全终止会话，而不会保留可下载的文件。

## 运行模型与分布式演进

MVP 的会话注册表使用单进程内存实现，从而不会引入数据库持久化，也使消息转发最短路径。可靠的双向 WebSocket 和原子双人锁定依赖单一持续运行实例；默认的无状态弹性模式不满足这一约束。生产运行应使用一台持续运行的受管实例，并将会话调度器与 WebSocket 中继置于同一个 Go 进程。

后续横向扩展通过 `SessionRegistry`、`PresenceBus` 和 `Clock` 接口完成。多实例实现可将仅含状态机元数据与绝对 TTL 的记录放入 Redis，使用 Lua 脚本实现加入/锁定/退出的原子变更，并以 Redis Pub/Sub 传递不落盘的密文中继事件；消息正文与文件分片都不进入持久队列。所有适配器均应拒绝在状态不可确定时继续会话，而不是尝试“猜测”恢复。

## 安全失败原则

服务端应启用 HTTPS/WSS、严格 Origin 白名单、每 IP 的创建/加入速率限制、消息和文件分片大小上限、有限的 WebSocket 读写期限、无内容日志和统一的关闭代码。错误发生时，客户端不缓存未送达明文，服务端不重试或排队密文，且会话在状态一致性不能保证时立即转入销毁。接口返回中不得包含密钥、明文文件名、消息正文或可复用的访问 URL。

## 部署前置条件

Go 后端需要自定义构建镜像来编译静态 Go 二进制并由其提供构建后的 Vue 静态资源。开发环境已安装 Go 1.22。该实现不需要数据库、对象存储、外部身份服务或第三方密钥；文件仅在会话存续期间的 WebSocket 流和浏览器内存中存在。

用户当前选择保留弹性托管模式。因此，该模式下的版本仅适用于预览、单实例受控访问或后续接入外部分布式状态适配器后的验证；它不能承诺两个 WebSocket 连接在扩缩容、冷启动或实例切换时始终命中同一内存会话。服务端遇到会话不存在或能力无效时将安全拒绝连接，而不会创建替代会话、恢复明文或放宽双人锁定规则。
