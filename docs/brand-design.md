# VeilRoom 品牌设计系统

**版本：0.1**  
**定位：匿名、短暂、双人、端到端加密的私密会话空间。**

> VeilRoom 不把“安全”讲成恐惧，也不把“加密”讲成晦涩。界面应当让用户自然感到：内容只属于此刻，系统值得信任，并且操作无需解释。

## 一、设计原则

| 原则 | 界面含义 | 实现准则 |
| --- | --- | --- |
| 加密 | 系统活着，但不窥视内容 | 用字节、哈希变换、连接状态和微弱辉光表达协议活动；不展示伪装的“锁”堆叠。 |
| 克制 | 每屏只保留一个主要动作 | 首页是“创建”；房间是“输入”；销毁页是“返回”。辅助内容退到低对比度层。 |
| 聪明 | 状态由行为与形状传达 | 倒计时、在线点、锁定态、禁用输入和短通知应当先于解释文案。 |
| 温和 | 隐私不需要压迫感 | 采用柔和边缘、低饱和青绿和浅紫，不用危险红来渲染正常加密状态。 |
| 轻盈 | 动效服务于理解，不占用注意力 | 动画仅修改 `opacity` 和 `transform`，常规过渡控制在 160–280ms。 |
| 内容优先 | 聊天内容永远是主角 | 会话页固定高度，消息区独立滚动；工具与状态固定在边缘，不能挤占消息空间。 |

## 二、视觉语言

### 2.1 色彩与材质

基础背景为接近纯黑的 `#07090c`，而非渐变大色块。页面背后使用低对比度的二进制字符场，字符亮度不得高于主文本的 18%，只在转换瞬间短暂模糊并发出微弱青绿辉光。这样传达“协议正在工作”，但不干扰阅读。

表层卡片采用深色半透明玻璃，建议使用 `rgba(16, 20, 25, .74)`、`backdrop-filter: blur(14px)` 和单像素低亮度边界。卡片不能依赖重阴影分组；内容层级由留白、文字权重与细边界建立。

强调色只保留两类：**协议青绿**用于创建、发送、连接正常与进度；**短暂浅紫**用于时间性和背景哈希的偶发变化。警告使用温和琥珀，错误只用于无法恢复的安全失败。

### 2.2 排版

中文主内容优先使用现代无衬线字体，标题应有明显但不过分的字距收紧；协议性元信息使用等宽字体，并以小写或数字节奏表达。大标题可以使用一处带有温度的衬线斜体作为记忆点，但聊天与状态区不得使用装饰字体。

标题字数应短。优先使用“只属于此刻”“会话已锁定”“还剩 01:00”这类信息密度高的表达，而非解释安全机制的长段文字。

### 2.3 标识

标识采用清晰的矢量化 `V` 轮廓与薄边容器，不使用旋转导致的模糊边缘。悬浮时仅发生 160ms 的轻微上移、边界亮度提升和内部字节光标闪烁；不缩放、不跳跃。

## 三、交互与动效规范

| 场景 | 行为 | 时间与缓动 |
| --- | --- | --- |
| 动态字节背景 | 以稀疏网格不断替换一小部分 `0/1`，替换前模糊、替换后清晰 | 900–1800ms 的错峰循环；用户启用减少动态时停止。 |
| 主按钮 | 悬浮时微弱边缘发亮，按下缩放到 0.98 | 160ms `cubic-bezier(.23,1,.32,1)`。 |
| 全局通知 | 视口上方正中进入，三秒后向上退场 | 入场与退场 260ms；进度条匀速 3s。 |
| 密钥确认 | 字符串从随机哈希逐步收束为确认标识 | 仅在建立会话的短时间出现，最长 900ms。 |
| 销毁 | 内容淡出、字节背景短暂失焦后回到首页 | 不用爆炸、碎裂或强警示动画。 |

键盘操作、错误修正和高频消息输入不应等待动效。所有非必要动画必须遵守 `prefers-reduced-motion`。

## 四、组件规则

### 4.1 按钮

主按钮使用暗色半透明底上的青绿内发光，不使用大面积纯色胶囊。按钮高度约 42–46px，半径 10–12px，图标和文字共同表达目的。次级按钮保持玻璃底和细边界；危险操作只在必要时使用琥珀或低饱和红的边界提示。

### 4.2 会话界面

桌面端使用三层结构：左侧状态轨、中央对话窗和底部邀请抽屉。邀请抽屉不得遮挡离开操作：状态轨必须有独立的内部滚动或将关键操作固定在其底部安全区域。移动端将状态压缩为顶部摘要，消息流占据剩余高度。

当一位参与者离开后，另一位保留在只读状态直至一分钟倒计时结束。界面以倒计时变为琥珀、输入框安静禁用和简短通知表达，不立刻跳转或关闭。

### 4.3 首页信息架构

首页顺序如下：

1. **首屏**：一句核心承诺、创建入口和低干扰的邀请入口。
2. **为什么选择 VeilRoom**：用三个交互卡片解释短暂、双人、无账户，而不是宣传列表。
3. **VeilRoom 的安全性**：用简明的协议路径展示浏览器加密、只转发密文、内存销毁和会话锁定。
4. **页脚**：只保留产品名、短暂会话的边界说明和最少导航。

## 五、实施边界与维护方式

此文档是所有后续设计修改的基线。任何新增页面、组件或动效应先回答以下问题：它是否降低用户理解成本？是否干扰内容？是否让“短暂、私密、仅两人”的产品事实更清晰？如果答案是否定的，不应进入界面。

每次视觉迭代后，应在本文件追加版本记录，写明调整的组件、原因、可访问性影响和验证方式。详细参考观察维护在 [`reference-notes.md`](./reference-notes.md)。

## 六、参考方向

本系统从 [Signal](https://signal.org/) 的隐私叙事、[Apple](https://www.apple.com/) 的材质与操作层级、[Telegram](https://telegram.org/) 的轻量反馈、[Element Plus](https://element-plus.org/en-US/component/overview) 的容器分层、[Kimi](https://www.kimi.com/en) 与 [Kimi Research](https://www.kimi.ai/blog/) 的内容优先技术气质、[Google Antigravity](https://antigravity.google/) 的动态表达，以及 [Vercel](https://vercel.com/) 的克制技术排版中提炼方向。VeilRoom 不复制任何一个参考站点的布局、图形或代码。
